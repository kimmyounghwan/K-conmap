# 한 번 고친 것은 다시 안 고치게 — 방안 (승인 대기)

적은 때: 2026-10-09 16:48 KST
소장님: 「업체 이것도 분명 고쳤거든. 고쳤는데 또 고치는 거잖아. 우선 방안 마련해. 한 번 고친 건 두 번 다시 고치지 않게.」

## 왜 또 고치게 됐나
- 9/18 «업체 선택» 고침 두 가지(CLAUDE.md 55 상호 표시 · 57 뒤로가기/고르는 자리)는 지금도 살아 있음.
- 10/9 G215 는 원인이 다름(아이폰 사파리 — 한글 조합 중 첫 누름이 안 옴). 그러나 소장님께는 같은 «업체 선택이 안 됨».
- 진짜 잘못 셋:
  1. 그때 **PC 로만** 확인함 — 폰(아이폰)으로 누르는 시험이 없었음.
  2. 화면 시험을 **/tmp 에 만들고 버림** — 저장소에 안 남아 다음에 다시 안 돌림.
  3. 올릴 때 도는 검사는 **3개(가져오기 · 금액 이름표 · 규칙)뿐** — tools/시험_*.mjs 62개는 올릴 때 안 돎.

## 방안
1. **고친 것 장부** (docs/고친것_장부.md) — 고칠 때마다 한 줄: 날짜 · 소장님 말(증상) · 원인 · 고친 파일 · 지키는 시험 이름.
   고치기 전에 장부부터 찾음 → 같은 증상이 있으면 «또 덧대기» 가 아니라 «왜 시험이 못 잡았나» 부터 고침.
2. **고칠 때마다 시험을 저장소에 남김** (tools/화면시험/) — 소장님 증상을 그대로 재현해
   «고치기 전 화면에서는 실패 · 고친 화면에서는 통과» 를 확인한 시험만 남김(G215 처럼).
3. **올릴 때마다 전부 돌림** — 올리기 bat 와 깃허브 자동 배포가 장부의 시험을 전부 돌리고, 하나라도 틀리면 **올리지 않고 멈춤**.
4. **PC 와 폰 둘 다** — 화면 시험은 PC(1280) · 폰(390 · 손가락 누름 · 아이폰처럼 click 안 옴 · 한글 조합 중) 두 벌로. 깃허브에서는 사파리 엔진(WebKit)으로도.
5. **같은 일은 한 부품으로** — 검색 목록 고르기가 여러 곳(업체 자가진단 · 발주기관 · 성적표 만들기)에 따로 있음 → 한 부품으로 모아 한 번 고치면 다 고쳐지게.

- 오늘 본 틀어짐 셋 — 모두 «사이트는 멀쩡히 굽혔는데 자료가 조용히 틀린» 것: ① 수집 형식이 바뀜(4~8월 번호 칸 없음 · 7월 파일 중간에 칸 추가) ② 읽기 실수(번호를 숫자로 읽어 9월 전부 버림) ③ 이름 체계 바뀜(전남광주통합특별시 → «광주»).
- 지금 health.json 은 «조달청에서 몇 줄 받았나» 만 봄(2회 연속 빔 → 메일). 자료의 «질» 은 안 봄.
- 안:
  1. 자료 검진(굽기 때마다): 달마다 1순위 건수 급감 · 사업자번호 비율(새 달 90%↑) · 대표 · 날짜 못 읽음 · 지역 못 정함 · 3년 창에 빈 달 없음 · 업체/기관 수 전날 대비 ±10% → health.json 에 «자료 검진» 칸.
