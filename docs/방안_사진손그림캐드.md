> 2026-10-14 10:52 KST 정리 · 소장님 「손그림, 사진 모두 정확도가 높아야 해. 웹사이트 검색 후 어떻게 만들 수 있는지 알려줘.」
> 2026-10-14 11:19 KST 고침 · 소장님 「무료로 도구를 만들어야 해」 → 유료 AI 빼고 **모두 이용자 기기 안에서 · 0원**.
> 앞선 말씀: 「사진을 주면 캐드로 주는 도구, 그림을 그려서 줘도 캐드로 보여주는 도구 … 예쁘게 가능하냐」 · 「사진도 캐드로 되어야 해」
> 상태: **방안만 — 만들기는 소장님 «해» 뒤**(코드 손대지 않음).

---

## 1. 결론

- **AI 에게 그림을 통째로 맡기면 정확하지 않음.** AI(비전 모델)는 선 위치 · 교차 같은 기하에 약함 — 간단한 선 문제에서 네 모델 평균 58 %, 가장 좋은 모델 77.8 %(사람 100 %). 상용 평면도 서비스(RoomSketcher)도 손그림 · 실물 사진은 받지 않음.
- **정확도는 다섯 단계에서 나옴**: ① 사진 펴기(원근 보정) ② 선 찾기(컴퓨터 비전 · 픽셀 단위) ③ 반듯하게(직각 · 평행 · 끝점 맞춤) ④ **적힌 치수 숫자대로 길이 맞춤** ⑤ 확인 화면에서 사람이 고침.
- **무료로 만듦**: 다섯 단계 모두 공개 프로그램(OpenCV.js 등)으로 이용자 브라우저 안에서 — 서버 · API · 요금 없음. 유료 AI 는 쓰지 않음.
- 실물 사진은 **한 면(정면 · 입면)** 까지만 정확. 평면 전체는 여러 장 + 레이저 거리계(magicplan 같은 앱 영역) — 웹사이트로는 어려움.

---

## 2. 입력별 정확도 (예상)

| 입력 | 어떻게 | 정확도 |
|---|---|---|
| 도면 사진(인쇄 도면 · 화면 사진) | 네 모서리 펴기 + 아는 길이 1개(축척) + 치수 숫자 읽기 | 치수 적힌 곳은 숫자 그대로. 나머지는 픽셀로 잼 — 1 % 안팎 예상(1:100 이면 수십 mm) |
| 손그림 | 치수 숫자 적기(모눈종이 권장) → 반듯하게 + 숫자 맞춤 | 숫자 적은 선 = 정확 · 직각 · 평행 정확 · 숫자 없는 선은 비율로 추정(«추정» 표시) |
| 실물 사진(벽 · 입면 · 구조물) | 정면 1장 + 같은 면에 아는 길이 2개(줄자 · A4 · 표식) | 그 면만 맞음 — 튀어나온 것 · 다른 면은 틀림(표식과 다른 평면이면 오차 큼) |

## 3. 처리 차례

1. **올리기** — 폰 카메라 · 파일.
2. **펴기** — OpenCV.js: 흑백 → 윤곽(Canny) → 가장 큰 네모 → 원근 펴기(getPerspectiveTransform). 모서리는 손으로 끌어 고칠 수 있게.
3. **선 깨끗이** — 그림자 지우기(적응 임계) → 가늘게(1픽셀 뼈대) → 선분 찾기(LSD · Hough) → 원 · 호 맞추기.
4. **반듯하게** — 거의 수평 · 수직 → 딱 0 · 90° · 끝점 붙이기 · 평행 · 같은 길이 맞춤 · 겹선 합치기 · (손그림) 모눈에 맞춤.
5. **치수** — 숫자 «제안»(무료 OCR) 또는 이용자가 선 눌러 입력 → 가까운 치수선 · 벽에 붙임 → 길이를 숫자대로 다시 풂.
6. **확인 화면** — 원본 위에 결과 겹쳐 보기 · 의심 선 빨강 · 선 눌러 길이 고침 · 지우기 · 더하기.
7. **DXF** — 레이어(벽 · 창 · 문 · 치수 · 글자) · mm 단위 · 사이트의 BIM 물량 · 도면 PDF · 3D 보기로 바로 이어짐.

---

## 4. 기술 · 비용 — 0원

- **모두 이용자 브라우저 안에서**: 서버 · API · 요금 없음 · 사진은 기기 밖으로 안 나감(개인정보 걱정도 없음).
- **펴기 · 선 찾기**: OpenCV.js(공개 · 무료) — 용량이 커서 이 도구를 열 때만 받음.
- **인쇄 숫자 읽기**: Tesseract.js 또는 PaddleOCR 브라우저판(공개 · 무료 · 기기 안에서).
- **손글씨 숫자**: 무료 OCR 은 약함(Tesseract 를 그 사람 글씨로 가르쳐도 글자 정확도 평균 78 %) → 자동으로 읽은 숫자는 «제안» 으로만 보이고, **선을 눌러 숫자를 넣거나 «맞음» 을 누름**(가장 정확).
- 유료 AI(Claude 비전 · 장당 약 30원 예상)는 **안 씀**.
- 정확도는 펴기 · 반듯하게 · 숫자 맞춤 · 확인 화면에서 나오므로 무료여도 거의 같음 — 손글씨 숫자를 한 번씩 누르는 손이 더 갈 뿐.

## 5. 이용자 안내 (정확도를 가장 크게 올림)

- 위에서 똑바로 · 밝게 · 그림자 없이 · 종이 네 모서리가 다 나오게.
- 손그림: 진한 펜 · 모눈종이 · **치수 숫자 적기** · 벽은 두 줄 또는 굵게.
- 실물: 같은 면에 줄자 · A4 종이를 두고 정면에서.

## 6. 만드는 차례 · 시간 (예상)

| 단계 | 내용 | 시간 |
|---|---|---|
| 1 | 도면 사진 → DXF(펴기 · 선 · 반듯 · 축척 · 확인 화면 · DXF) | 3 ~ 4일 |
| 2 | 손그림(모눈 · 반듯 강화 · 숫자 직접 입력 → 길이 맞춤) | 2 ~ 3일 |
| 3 | 숫자 자동 «제안»(무료 OCR · 기기 안 · 이용자가 확인) | 1 ~ 2일 |
| 4 | 실물 사진 정면(입면) | 2일 |
| — | 정확도 맞추기: 실제 사진 · 손그림 10 ~ 20장으로 정답 DXF 와 비교 | 계속 |

## 7-1. 지금 팔리는 것의 수준 (2026-10-14 16:20 KST 소장님 「지금 상용화 되고 있는 건 어느 정도 수준이지??」)

- **결론**: 어디나 «자동으로 대부분 + 치수 하나로 크기 맞춤 + 사람이 고침». 완전 자동으로 정확한 것은 없음 · 정확도 숫자를 내놓는 곳도 거의 없음. 한국은 아직 크몽 등에서 **사람이 직접 다시 그려 주는 대행**(5,000원부터 · 2일)이 흔함.
- **도면 스캔 · 이미지 → 캐드(가장 오래됨)**: AutoCAD Raster Design(AutoCAD 2026 에 포함 · 이미지 정리 · 선 · 폴리선으로) · Scan2CAD(직선 · 글자는 잘 됨 · 곡선 · 호 약함 · JPEG 약함 · 리뷰 «80 % 쯤 해 줌») · ZWCAD 벡터화(유료 · 5일 체험) · Raster2CAD(AI 레이어 나누기 · 아직 초기).
- **평면도 사진 · 손그림 → 캐드(AI · 최근)**: Polycam 평면도 디지타이저(사진 · 손그림 받음 · 벽 · 문 · 창 · 벽 하나 길이 넣으면 전체 맞춤 · DWG/DXF · 유료) · PhotoCAD(사진 → DXF/DWG · 무료 3장 · 월 12.5 ~ 41달러 · 정확도 숫자 없음) · Extruda(«깨끗한 손그림은 잘 · 거친 건 고쳐야 · 치수 하나 넣어야 정확 · 시공엔 실측 확인»).
- **실물(방 · 건물) → 평면도(측정 장비)**: Polycam LiDAR ±½인치(약 1.3 cm) · 사진만으론 치수 부정확(기준 길이로 다시 맞춰야) · CubiCasa 폰 스캔 + 사람 검수 95 ~ 99 %(장당 22.99달러부터) · iGUIDE 전용 카메라 ±0.5 %(장비 2,000 ~ 2,500달러) · magicplan AR + 레이저 거리계.
- 우리 방안(자동 · 치수 숫자로 맞춤 · 확인 화면)은 상용과 같은 방식 — 다른 점은 무료 · 기기 안 · 건설 도면(치수 숫자) 중심.
