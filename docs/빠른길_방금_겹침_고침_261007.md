# 1순위·공고 «🆕 방금» 겹침 — 원인과 고친 방안 (G193 · 2026-10-07 20:22 KST)

## 증상
- 소장님 폰 2026-10-07 20:07, /first(1순위): 오전 11:00 개찰(허준박물관 보행로 조명 전기공사, 2026년 배수문 12개소, 하반기 도로시설물 …)이 «🆕 방금» 표를 달고 17:30 개찰보다 위에 떴음.
- 숫자(1순위 업체·투찰률·참가 업체 수)는 맞고, **순서와 «방금» 표시만 틀림**.

## 원인 (실제 사이트 자료로 확인)
- 1순위 목록은 500건씩 묶어서 올림. 그날 0번 묶음 = 17:30 ~ 11:00, 1번 묶음 = 11:00 ~ 10.2 → **11:00 개찰이 두 묶음에 걸쳐 나뉨**.
- 빠른 수집(fast.py, 10분마다)은 **0번 묶음만** 보고 «없고 + 0번 묶음의 가장 오래된 시각(11:00)보다 오래되지 않은 것»을 새 것으로 봄.
- 그래서 1번 묶음으로 넘어간 11:00 개찰 **94건**을 «방금»으로 다시 올림(데이터베이스 fresh/rows/first 94건 모두 10.07 11시).
- 화면(lib/fresh.js)은 받아 둔 묶음(0번)과만 겹침을 지우므로 그대로 맨 위에 얹음.
- 공고(/live)도 같은 구조라 같은 일이 날 수 있었음.

## 고친 방안 — 두 겹
1. **빠른 수집(fast.py)**: 0번 묶음이 꽉 찼으면(500건) 같은 시각 무리가 넘어간 뒤 묶음(1번 …, 최대 3개)까지 받아 «사이트에 있는 것»에 넣음(known_on_site).
   - 뒤 묶음을 못 받으면 그 회차는 경계 시각과 같은 줄을 «방금»에서 뺌(겹치는 것보다 낫게).
   - 비용: 10분마다 사이트 파일 하나 더 받음(수백 KB) — 거의 0.
2. **화면(lib/fresh.js · useBoard.js · FirstBoard · LiveBoard)**: 뒤 묶음이 더 있을 때, 받아 둔 묶음의 가장 오래된 시각과 **같거나 더 오래된** 빠른 줄은 얹지 않음(바닥시각 · freshRows floor).
   - 까닭: 정기 배포 직후 빠른 수집이 아직 옛 목록 기준일 때(최대 10분)도 겹치지 않게.
   - 영향: 경계 시각에 늦게 올라온 «진짜 새 줄»은 다음 정기 배포 때 제자리(2쪽 이후)에 나옴 — 첫 화면 «방금» 이 아님.
